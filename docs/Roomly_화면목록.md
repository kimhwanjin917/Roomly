# Roomly 화면 목록

---

## 페이지 구조 개요

```
/
├── /login                        관리자 로그인
├── /forgot-password              비밀번호 재설정 요청 (이메일 발송)
├── /reset-password               새 비밀번호 설정 (이메일 링크 경유)
├── /guest                        게스트(일일알바) 접속 코드 입력 (?h={hotelId} 파라미터 필수)
├── /admin                        전체 객실 현황판 (메인)
│   ├── /admin/rooms              객실 추가·관리
│   ├── /admin/staff              직원 관리
│   └── /admin/stats              일일 통계
├── /worker/[staffId]             고정 직원 화면 — 하우스키핑 (QR 접속)
├── /worker/dirty/[staffId]       고정 직원 화면 — Dirty Worker (QR 접속)
└── /worker/guest                 게스트 작업 화면
```

---

## 1. 로그인 — `/login`

**접근 권한**: 누구나 (비로그인)  
**역할**: 관리자 인증 진입점

### 구성 요소
- 호텔 로고 / 서비스명
- 이메일 입력 필드
- 비밀번호 입력 필드
- 로그인 버튼
- 로그인 실패 에러 메시지
- QR 만료 시 amber 배너 (`?error=qr_expired`)
- 비밀번호 재설정 완료 시 안내 배너 (`?reset=1`)

### 동작
- 로그인 성공 → `/admin` 이동
- 이미 로그인 상태 → 자동으로 `/admin` 리다이렉트
- 하단 "일일 근무자 입장 →" 링크 → `/guest`로 이동 (일일알바용)
- "비밀번호를 잊으셨나요?" 링크 → `/forgot-password` 이동

---

## 2. 비밀번호 찾기 — `/forgot-password`

**접근 권한**: 누구나 (비로그인)  
**역할**: 관리자 비밀번호 재설정 이메일 발송

### 구성 요소
- "← 로그인으로 돌아가기" 링크
- 관리자 이메일 입력 필드
- [재설정 링크 받기] 버튼
- 발송 완료 안내 (전송 후 성공 메시지로 전환)

### 동작
- `supabase.auth.resetPasswordForEmail()` 호출
- 리다이렉트 URL: `/auth/callback?type=recovery`
- 발송 성공 → "이메일을 확인해주세요" 화면으로 전환
- 이메일 미존재 계정도 동일 성공 메시지 표시 (계정 존재 여부 노출 방지)

---

## 3. 새 비밀번호 설정 — `/reset-password`

**접근 권한**: Supabase 이메일 링크 경유자만 (세션 자동 주입)  
**역할**: 비밀번호 재설정 완료

> 접근 경로: 이메일 링크 → `/auth/callback?type=recovery` → `/reset-password`

### 구성 요소
- 새 비밀번호 입력 (8자 이상)
- 비밀번호 확인 입력
- [비밀번호 변경] 버튼

### 동작
- `supabase.auth.updateUser({ password })` 호출
- 성공 → `supabase.auth.signOut()` 후 `/login?reset=1` 이동 (로그인 페이지에서 완료 배너 표시)
- 링크 만료 시 에러 메시지 표시

---

## 4. 게스트 접속 — `/guest`

**접근 권한**: 누구나 (비로그인)  
**역할**: 일일알바가 로그인 없이 당일 접속 코드만 입력해 작업 화면 진입

> **URL 형식**: `/guest?h={hotelId}`  
> `h` 파라미터(호텔 UUID)가 없으면 "잘못된 접속 링크입니다" 표시 후 진행 불가.  
> 관리자가 게스트 코드 발급 시 이 URL을 함께 표시해 일일알바에게 전달한다.

### 구성 요소
- 서비스명 / 안내 문구 ("오늘의 접속 코드를 입력하세요")
- 6자리 코드 입력 필드
- [입장] 버튼
- 에러 메시지 (코드 틀림 / 만료 / 호텔 파라미터 없음)

### 동작
- 페이지 로드 시 `?h` 파라미터 확인 → 없으면 즉시 에러 메시지 표시, 입력 폼 비활성화
- 코드 검증 성공 → 게스트 JWT 발급 → `/worker/guest` 이동
- 당일 자정 이후 코드 만료 → "오늘의 코드가 만료되었습니다. 관리자에게 문의하세요"

---

## 5. 전체 객실 현황판 — `/admin`

**접근 권한**: 관리자만  
**역할**: 핵심 화면. 모든 객실 상태를 한눈에 파악하고 배정

### 구성 요소

#### 상단 헤더
- 호텔명
- 현재 날짜/시간
- 로그아웃 버튼
- 네비게이션 (현황판 / 객실관리 / 직원관리 / 통계)

#### 필터 바
- 층별 필터 (전체 / 1층 / 2층 / ...)
- 상태별 필터 (전체 / 더티 / 청소중 / 완료 / 점검대기)
- 담당 직원별 필터

#### 객실 그리드
- 객실 카드 (번호, 상태, 담당 직원명, 체크인 시간)
- 상태별 색상 구분
  - 더티: 회색
  - 청소중: 노란색
  - 완료: 초록색
  - 점검대기: 보라색
  - 체크인 2시간 이내 미완료: 빨간색 테두리 + 경고 아이콘 (색맹 대응)
- 카드 클릭 → 배정 모달 열림

#### 배정 모달
- 객실 번호 / 현재 상태
- 담당 직원 선택 드롭다운 (직원 목록 + "게스트" 선택지 포함 → 게스트 풀 배정)
- 배정 확정 버튼
- 상태 수동 변경 버튼 (관리자 강제 변경용)
  - dirty → cleaning / done / inspect
  - cleaning → dirty / done / inspect
  - done → dirty (재청소 필요 시)
  - inspect → done / dirty
- 메모 입력란

#### 요약 카운터 (상단 또는 사이드)
- 더티 N개 / 청소중 N개 / 완료 N개 / 점검대기 N개

### 동작
- 실시간 상태 반영 (Supabase Realtime 구독)
- 체크인 2시간 전 자동 긴급 표시 (60초 인터벌 폴링 — 화면 마운트 시 시작, 언마운트 시 중단)

---

## 6. 객실 관리 — `/admin/rooms`

**접근 권한**: 관리자만  
**역할**: 초기 세팅 및 객실 추가·수정·삭제

### 구성 요소
- 객실 목록 테이블 (호수, 층, 타입, 현재 상태)
- 객실 추가 버튼 → 모달
  - 호수 입력
  - 층 입력
  - 타입 선택 (싱글 / 더블 / 스위트 / 기타)
- 객실 수정 / 삭제 버튼 (행마다)

### 동작
- 삭제 시 확인 다이얼로그
- 삭제는 **소프트 삭제** (`rooms.deleted_at = now()` 업데이트). 물리 삭제 금지
- 삭제된 객실은 현황판·목록에서 즉시 숨김 (`deleted_at IS NULL` 필터)
- room_logs·assignments 이력은 그대로 보존됨 (물리 삭제가 아니므로 CASCADE 미발동)

---

## 7. 직원 관리 — `/admin/staff`

**접근 권한**: 관리자만  
**역할**: 직원 등록, QR 발급, 삭제, 게스트 코드 발급

### 구성 요소
- 직원 목록 테이블 (이름 / 연락처 / 역할 / 현재 담당 객실 수 / QR 상태)
- 직원 추가 버튼 → 모달
  - 이름 입력
  - 연락처(전화번호) 입력
  - 역할 선택: 하우스키핑 / Dirty Worker
  - 저장 시 QR 자동 생성
- QR 보기 / 재발급 버튼 (직원 행마다)
- 직원 삭제 버튼
- [오늘의 게스트 코드 발급] 버튼 (섹션 분리)
  - 발급 시 6자리 코드 표시 + 복사 버튼
  - 게스트 접속 URL 표시 + 복사 버튼 (`NEXT_PUBLIC_APP_URL/guest?h={hotelId}`)
  - 당일 자정 만료 안내
  - 전달 방법: 코드와 URL을 카톡 등으로 일일알바에게 전달

### 동작
- QR 보기 → QR 이미지 모달 (다운로드 가능)
- 삭제 시 확인 다이얼로그

---

## 8. 일일 통계 — `/admin/stats`

**접근 권한**: 관리자만  
**역할**: 하루 처리 현황 요약

### 구성 요소
- 날짜 선택기 (기본값: 오늘)
- 전체 완료 객실 수 / 전체 객실 수
- 직원별 완료 객실 수
- 직원별 평균 처리 시간
  - 집계 대상: `completed_at IS NOT NULL` 인 row만 (취소된 배정 제외)
  - 계산식: `AVG(completed_at - assigned_at)` per staff_id
  - 재배정 케이스에서 기존 배정은 `cancelled_at`이 기록되므로 자동 제외됨
- 미완료 객실 목록

---

## 9. 고정 직원 화면 — 하우스키핑 — `/worker/[staffId]`

**접근 권한**: staffId에 해당하는 직원 (QR 링크 = JWT 세션 토큰 인증, `worker_role: 'housekeeping'`)  
**역할**: 직원이 배정된 방을 확인하고 상태 처리

### 구성 요소

#### 상단
- "안녕하세요, [이름]님" 인사
- 현재 날짜

#### 배정 목록
- 우선순위 순 정렬 (체크인 임박 방 상단)
- 객실 카드 (번호, 층, 객실 타입, 체크인 시간)
- 긴급 표시: 빨간 배지 + "긴급" 텍스트 (색맹 대응)
- 상태 버튼
  - [청소 시작] → cleaning
  - [완료] → done
  - [점검 필요] → inspect
  - [대기중으로 되돌리기] → dirty (청소 시작 실수 시 취소용, cleaning 상태일 때만 표시)

#### 메모
- 완료 처리 시 메모 입력 옵션 (선택사항)

### 동작
- 버튼 탭 → 즉시 상태 변경 + 관리자 화면 실시간 반영
- 완료된 방은 목록 하단으로 이동 또는 흐리게 처리
- 오프라인 상태 시: 마지막 배정 목록 캐시 표시 + "오프라인" 배너

---

## 10. 고정 직원 화면 — Dirty Worker — `/worker/dirty/[staffId]`

**접근 권한**: staffId에 해당하는 직원 (QR 링크 = JWT 세션 토큰 인증, `worker_role: 'dirty'`)  
**역할**: 호텔 전체 객실 중 체크아웃(done/inspect)된 방을 dirty로 처리하는 전담 직원 화면

> 배정 개념 없음. 전체 객실이 항상 표시되며, done/inspect 상태의 방을 dirty로 전환하는 단순 작업 화면.

### 구성 요소

#### 상단 헤더
- "안녕하세요, [이름]님" 인사
- 현재 날짜
- 요약 카운터: 더티 완료 N개 / 더티 대기 N개 / 전체 객실 N개

#### 층별 객실 그리드
- 층별 그룹으로 묶인 객실 카드 (3열 그리드)
- 카드 상태별 표시:
  - done / inspect (더티 대기): 노란색 테두리 + "더티 ↓" 배지 → 탭하면 dirty 처리
  - dirty (이미 처리됨): 회색 + "✓ 더티" 표시, 비활성
  - cleaning (청소중): 회색 + 상태 표시, 비활성 (건드리지 않음)

### 동작
- 카드 탭 → `POST /api/worker/dirty/status` → 상태를 `dirty`로 변경
- Supabase Realtime으로 다른 직원 처리 사항 실시간 반영
- 오프라인 배너 표시

---

## 11. 게스트 작업 화면 — `/worker/guest`

**접근 권한**: 당일 유효한 게스트 JWT 보유자  
**역할**: 일일알바가 게스트 풀에 배정된 방만 처리

### 구성 요소
- "게스트" 표시 (이름 없음)
- 현재 날짜
- 게스트 풀 배정 목록 (관리자가 게스트 슬롯에 배정한 방만 표시)
- 상태 버튼: [청소 시작] / [완료] / [점검 필요]
- [대기중으로 되돌리기] → dirty (cleaning 상태일 때만 표시)
- 메모 입력 (선택사항)

### 동작
- 고정 직원 화면과 동일하게 상태 변경 + 실시간 반영
- 다른 직원 배정 방, 전체 현황 접근 불가
- 당일 자정에 세션 자동 만료
