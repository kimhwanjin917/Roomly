# Roomly 온보딩 전략

> 목표: 가입 후 72시간 내 "첫 배정 완료"까지 도달하는 비율을 높인다.  
> 이 지표 하나가 3개월 후 유료 전환율과 가장 강하게 연관된다.

---

## 1. 핵심 개념: Activation Moment

Roomly의 **Activation Moment**(가치를 처음 체감하는 순간)는 다음 두 가지가 동시에 일어날 때다.

1. 관리자가 객실을 배정한다
2. 직원 폰에 알림이 온다

이 순간 전에 이탈하면 3개월 체험이 있어도 의미 없다.  
이 순간을 경험한 사람은 높은 확률로 다음 날에도 로그인한다.

**설계 원칙**: 모든 온보딩 기능은 이 순간을 최대한 빠르게 만드는 데 집중한다.

---

## 2. 이탈 구간 지도

```
가입
  │
  ├─ [이탈 구간 A] 객실 미등록 → 가입 후 24h 이내 40~60% 이탈 예상
  │     원인: 객실을 하나씩 입력하는 게 귀찮다
  │     해결: 일괄 등록 기능
  │
  ├─ 객실 등록 완료
  │
  ├─ [이탈 구간 B] 직원 미추가 or QR 미공유 → 24~72h 이내 추가 이탈
  │     원인: QR 출력 방법을 모른다 / iOS에서 QR이 안 된다고 느낌
  │     해결: QR 출력 가이드 모달 + iOS 설치 가이드
  │
  ├─ 첫 배정 완료 ← Activation Moment
  │
  ├─ [이탈 구간 C] 7일 이내 이탈 → 사용했지만 의미를 못 느낌
  │     원인: PMS 이중 입력 불편 / 직원들이 결국 카톡 씀
  │     해결: D7 리포트 이메일 ("지난 7일 절약한 것")
  │
  └─ 3개월 체험 만료 → 유료 전환 또는 이탈
        원인: "그래서 얼마나 좋아졌지?"를 숫자로 모름
        해결: D83 통계 이메일 (체험 종료 7일 전 자동 발송)
```

## 3. 이메일 시퀀스

현재 인프라: Resend + `@react-email` + Vercel Cron  
기존 파일: `emails/WelcomeEmail.tsx`, `emails/DailyReportEmail.tsx`  
기존 크론: `app/api/cron/daily-report/route.ts`

### 필요한 이메일 5종

| 타이밍 | 이름 | 발송 조건 | 목적 |
|--------|------|-----------|------|
| D+0 (가입 직후) | 웰컴 이메일 | 항상 | 시작 3단계 안내 |
| D+1 | 객실 미등록 리마인더 | 객실 0개인 경우만 | 이탈 구간 A 방어 |
| D+3 | QR 공유 확인 | 직원 > 0 but 배정 없는 경우 | 이탈 구간 B 방어 |
| D+7 | 첫 주 리포트 | 배정 1회 이상 완료한 경우 | 가치 증명 + 습관화 |
| D+83 | 체험 종료 전 통계 | 체험 만료 7일 전 | 유료 전환 설득 |

### 각 이메일 핵심 메시지

**D+1 — 객실 미등록 리마인더**
```
제목: [Roomly] 아직 객실을 등록하지 않으셨네요

{hotelName} 관리자님, 어제 가입하셨는데 아직 객실 등록이 안 됐어요.
객실 한 개만 등록하면 현황판을 바로 쓸 수 있습니다.

→ [객실 등록하기] 버튼 (링크: /admin/rooms)

10개 객실을 한 번에 등록하는 방법도 있어요. → [일괄 등록 가이드]
```

**D+3 — QR 공유 확인**
```
제목: [Roomly] 직원들이 아직 QR을 받지 못했어요

직원을 등록하셨는데, 아직 첫 배정이 없어요.
QR 코드를 출력해서 직원 폰으로 스캔해 보셨나요?

→ [QR 코드 출력하기] (링크: /admin/staff)

iPhone 사용 직원이 있다면 이 가이드를 먼저 보세요. → [iOS 설치 안내]
```

**D+7 — 첫 주 리포트**
```
제목: [Roomly] {hotelName}의 첫 7일 현황

지난 7일 동안:
- 청소 완료: {completedCount}건
- 평균 완료 시간: {avgMinutes}분
- 가장 빠른 직원: {topStaff}

이 숫자가 매주 쌓입니다. 다음 주에 또 보내드릴게요.
```

**D+83 — 체험 종료 전 통계**
```
제목: [Roomly] 3개월 체험이 7일 후 종료됩니다

{hotelName}의 3개월 성과:
- 총 청소 완료: {totalCompleted}건
- 평균 완료 시간: {avgMinutes}분 (업계 평균 대비 {diff}분 빠름)
- 가장 활발한 직원: {topStaff}

계속 사용하시려면 플랜을 선택해 주세요.
→ [요금제 보기] (링크: /admin/billing)
```

### 크론 구현 계획

```
새로 만들 파일:
app/api/cron/onboarding-d1/route.ts   → 매일 실행, 가입 24~48h + 객실 0개인 호텔
app/api/cron/onboarding-d3/route.ts   → 매일 실행, 가입 72~96h + 배정 0건인 호텔
app/api/cron/onboarding-d7/route.ts   → 매일 실행, 가입 7~8일 + 배정 1건 이상
app/api/cron/trial-ending/route.ts    → 매일 실행, plan_expires_at 7일 전
```

`vercel.json`에 cron 스케줄 추가:
```json
{
  "crons": [
    { "path": "/api/cron/onboarding-d1", "schedule": "0 10 * * *" },
    { "path": "/api/cron/onboarding-d3", "schedule": "0 10 * * *" },
    { "path": "/api/cron/onboarding-d7", "schedule": "0 10 * * *" },
    { "path": "/api/cron/trial-ending",  "schedule": "0 9  * * *" }
  ]
}
```

## 4. 인앱 기능 우선순위

### 우선순위 1 (이탈 구간 A — 객실 등록)

**객실 범위 일괄 등록**
- 현재: 한 개씩 입력 (`app/admin/onboarding/OnboardingWizard.tsx`)
- 필요: "101 ~ 110호, 2층, 더블" 한 줄로 10개 등록
- 구현 위치: `OnboardingWizard.tsx` Step 1에 "일괄 등록" 탭 추가
- API: `app/api/admin/rooms/route.ts`에 배열 입력 지원 추가

```
[일괄 등록] 탭 UI:
시작 호수: [101]  끝 호수: [110]  층: [1]  타입: [더블 ▼]
→ 10개 객실이 한 번에 등록됩니다
```

---

### 우선순위 2 (이탈 구간 B — QR 공유)

**QR 인쇄 가이드 모달**
- 현재: QR 이미지만 있음 (`app/api/admin/staff/[id]/qr/route.ts`)
- 필요: "이렇게 출력하세요" 단계별 설명 + 인쇄 버튼
- 구현 위치: `app/admin/staff/page.tsx`에 QR 모달 개선

모달 내용:
```
1. 아래 QR을 인쇄하거나 캡처하세요
2. 직원 폰으로 QR을 스캔하게 하세요
3. "홈 화면에 추가"를 눌러 앱처럼 설치하세요 (iPhone은 Safari 필수)
[QR 이미지]  [인쇄하기]
```

**iOS PWA 설치 안내**
- 직원이 Chrome(안드로이드)이 아닌 경우를 위한 별도 안내
- 구현 위치: `app/worker/[staffId]/WorkerDashboard.tsx`에 iOS 감지 후 배너 노출
- 조건: `navigator.userAgent.includes('iPhone')` && `!window.navigator.standalone`

```
[iPhone 감지 시 배너]
홈 화면에 추가하면 알림을 받을 수 있어요.
Safari → 공유 버튼 → 홈 화면에 추가
```

---

### 우선순위 3 (활성화 확인)

**직원 첫 QR 접속 시 관리자 알림**

현재 직원이 QR로 처음 접속해도 관리자는 알 수 없다. 이 시점이 가장 중요한 신호다.

- 구현 위치: `app/api/auth/qr/route.ts`에 첫 접속 감지 로직 추가
- 첫 접속 감지: `staff` 테이블에 `first_accessed_at` 컬럼 추가
- 감지 시: 관리자에게 푸시 알림 + 이메일 발송

```
"김청소 직원이 처음으로 QR로 접속했습니다. 이제 배정을 시작하세요!"
→ [배정하러 가기] 링크
```

---

### 우선순위 4 (습관화)

**현황판 빈 상태 개선**

현재: `AdminDashboard.tsx`의 빈 상태가 단순 텍스트  
필요: 온보딩 체크리스트로 바로 안내 (이미 체크리스트 컴포넌트 추가됨 → 자동 해결)

**주간 리포트 이메일 고도화**

현재: 일일 리포트만 있음 (`app/api/cron/daily-report/route.ts`)  
추가: 7일 집계 + "지난주 대비 X% 빠름" 비교 지표

## 5. 측정 지표

온보딩 전략이 작동하는지 판단하는 지표 3개만 집중한다.

| 지표 | 정의 | 목표 | 측정 방법 |
|------|------|------|-----------|
| **D3 Activation Rate** | 가입 후 3일 내 첫 배정 완료 비율 | 40% 이상 | `assignments` 테이블에서 가입일 + 3일 내 completed_at |
| **D7 Retention** | 가입 후 7일째에도 로그인한 비율 | 50% 이상 | `hotels` 테이블에 `last_active_at` 컬럼 추가 필요 |
| **3개월 전환율** | 체험 만료 후 유료 전환 비율 | 25% 이상 | Stripe 웹훅 + `hotels.subscription_plan` 변경 추적 |

D3 Activation Rate가 40% 미만이면 이탈 구간 A/B 문제.  
D7 Retention이 50% 미만이면 Activation Moment 자체가 가치를 전달 못 하는 것.  
3개월 전환율이 25% 미만이면 D83 이메일과 가치 증명 리포트 문제.

## 6. 구현 순서 요약

```
Phase 1 — 이번 주 (이탈 방어)
  ✅ 온보딩 체크리스트 컴포넌트 (완료)
  □ 객실 범위 일괄 등록 UI
  □ QR 인쇄 가이드 모달 개선
  □ D+1 리마인더 이메일 + 크론

Phase 2 — 다음 주 (가치 증명)
  □ D+3 QR 공유 확인 이메일
  □ D+7 첫 주 리포트 이메일
  □ iOS PWA 설치 안내 배너 (WorkerDashboard)
  □ 직원 첫 QR 접속 시 관리자 푸시 알림

Phase 3 — 3주차 (전환 최적화)
  □ D+83 체험 종료 전 통계 이메일
  □ 주간 리포트 이메일 (일일 → 주간 집계)
  □ last_active_at 추적 + D7 Retention 대시보드
```

## 7. 지금 당장 하지 말아야 할 것

- AI 기능 추가 — 사용자 데이터가 없으면 의미 없음
- PMS 연동 — 온보딩이 안정되기 전에 연동하면 복잡도만 올라감
- 다국어 지원 — 국내 PMF 먼저
- 알림 채널 추가 (카카오 알림톡 등) — 이메일 + 푸시로 충분히 검증 후
